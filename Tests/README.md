# Тесты главной страницы и каталога

Требования: [задача №26 «Тестирование»](https://github.com/Viatlyyy/ROBINxBLOCK-ShoeStore/issues/26), связанная с [задачей №24](https://github.com/Viatlyyy/ROBINxBLOCK-ShoeStore/issues/24).

## Запуск

Из корня проекта:

```powershell
dotnet test ShoeStore.sln
```

Нужны SDK .NET 9 или более новый совместимый SDK и среда выполнения .NET 9. При первом запуске NuGet восстановит пакеты MSTest и Moq. В Visual Studio тесты доступны через «Тест → Обозреватель тестов».

Автоматические тесты не запускают веб-сервер и не подключаются к PostgreSQL. Строка подключения и User Secrets для них не нужны. Каждый сценарий `DataRow` выполняется как отдельный тест.

## Автоматические проверки

| Файл | Что проверяется | Количество сценариев |
|---|---|---:|
| `ShoeStore.Tests/Unit/TProduct.cs` | Обязательные название и описание; пределы 100 и 2000 символов; цена от 1 до 999999 включительно; корректные данные и допустимые границы. | 16 |
| `ShoeStore.Tests/Unit/TProductVariant.cs` | Обязательные название расцветки, артикул, цвет и изображение; пределы 80, 64, 24 и 512 символов; корректные данные и допустимые границы. | 18 |
| `ShoeStore.Tests/Mocks/THomeController.cs` | Получение данных главной страницы ровно один раз; передача токена отмены; возврат `ViewResult` с исходной `HomePageViewModel`; пустые списки; вызов без аргументов. | 3 |
| `ShoeStore.Tests/Mocks/TCatalogController.cs` | Возврат `ViewResult` с исходной `CatalogPageViewModel`; передача номера страницы и токена; первая страница по умолчанию; пустой список. | 6 |
| **Всего** | | **43** |

Валидация выполняется через настоящий `Validator.TryValidateObject` со всеми атрибутами свойств. В отрицательных сценариях меняется только одно поле и проверяется, что ошибка относится именно к нему. Пустые значения проверяются как `null`, пустая строка и пробельная строка. Для цены отдельно проверяются дробные значения `0.99` и `999999.01` за пределами диапазона.

Контроллеры получают строгий мок `ICatalogQueryService`. Тесты вызывают настоящие действия контроллеров и проверяют результат; получение данных из PostgreSQL этими тестами не покрывается.

## Организация

Автоматические тесты разделены на две папки внутри `ShoeStore.Tests`:

- `Unit` — валидация моделей `Product` и `ProductVariant`.
- `Mocks` — проверки `HomeController` и `CatalogController` с моками `ICatalogQueryService`.

Папка `Database` и старые тесты регистрации/авторизации удалены из проекта по запросу; база на сервере не изменяется.

# План ручного тестирования регистрации

Откройте `ShoeStore.sln`, выберите приложение `ShoeStore` запускаемым проектом и запустите его. Настройте подключение приложения к отдельной тестовой БД с таблицами регистрации и откройте `/Account/Register`.

Для каждого успешного сценария используйте новый e-mail, например `manual-registration-01@example.com`. Тестовый пароль: `TestPass1!`. В остальных сценариях заполните все поля корректно, кроме проверяемого поля.

| № | Сценарий и действия | Ожидаемый результат |
|---|---|---|
| 1 | Ввести имя «Виталий», новый e-mail, `TestPass1!` в оба поля пароля, принять условия и нажать «Создать аккаунт». | Появляется «Регистрация успешно завершена.». В тестовой БД создан один пользователь с ролью `Customer`; имя «Виталий» сохранено как `GivenName` в `AspNetUserClaims`. В `PasswordHash` записан хеш, а не введённый пароль. |
| 2 | Оставить обязательные поля пустыми и отправить форму. Затем повторить с одним пустым полем за раз. | Аккаунт не создаётся. Над формой выводятся сообщения «Введите имя.», «Введите адрес электронной почты.», «Введите пароль.» и/или «Повторите пароль.» для соответствующих полей. |
| 3 | По очереди ввести одинаковые значения в оба поля пароля: `Aa1!abc` (7 символов), `testpass1!` (без заглавной), `TESTPASS1!` (без строчной), `TestPass!!` (без цифры), `TestPass11` (без специального символа). | Аккаунт не создаётся. Для короткого пароля: «Пароль должен содержать от 8 до 128 символов.». Для остальных случаев — сообщение о недостающей заглавной букве, строчной букве, цифре или специальном символе. |
| 4 | В поле пароля ввести `TestPass1!`, в подтверждение — `OtherPass1!`, отправить форму. | Аккаунт не создаётся. Над формой появляется «Пароли не совпадают.». |
| 5 | Заполнить поля правильно, оставить согласие с условиями выключенным и отправить форму. | Аккаунт не создаётся. Над формой появляется «Необходимо принять условия использования и политику конфиденциальности.». |

При каждом отказе пользователь остаётся на странице регистрации. Сообщения не содержат введённый пароль или технические подробности исключений.

Записывайте результат каждого сценария: «пройден» или «не пройден», дату и обнаруженные проблемы. Этот документ — план; автоматические тесты не заменяют проверку отображения страницы человеком.
